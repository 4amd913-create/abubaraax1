# FAR3ON VPS — Enhanced Static Edition

نسخة مطوّرة من الموقع التعريفي، جاهزة للنشر على Cloudflare Pages. تحسّن هذه الحزمة الأمان على مستوى ملفات الموقع، وتضيف صفحات الخصوصية والشروط والأخطاء وفحوصات CI ودليلًا مفصلًا لتجهيز البنية المستقبلية.

## ما أُضيف

- ترويسات أمان أقوى عبر `_headers`، وسياسة CSP دون `unsafe-inline`.
- تخزين مؤقت للملفات الثابتة مع إعادة التحقق من صفحات HTML.
- صفحة 404 تلقائية لـ Cloudflare Pages، وقالب 500 للاستخدام عند إضافة معالج أخطاء ديناميكي.
- مسودتا سياسة الخصوصية وشروط الاستخدام، مع توضيح أن الموقع لا يخزن الاستفسارات حاليًا.
- قسم مرئي يشرح معايير تشغيل VPS المستقبلية مع تأكيد أنها ليست مفعلة في الوقت الحالي.
- تحسينات وصول لوحة المفاتيح، نموذج الاستفسار، وإغلاق قائمة الهاتف.
- GitHub Actions للتحقق من الملفات والروابط المحلية وسياسة CSP.
- دليل إنتاج يوضح ما ينطبق على Cloudflare Pages وما يحتاج VPS مستقلًا.

## ما لا تفعله النسخة

هذه ليست منصة VPS فعلية. لا يوجد خادم Linux تحت إدارتك أو قاعدة بيانات أو API أو حسابات أو لوحة إدارة أو دفع إلكتروني. لذلك لا يمكن تفعيل SSH/UFW/Fail2ban/systemd/logrotate أو نسخ قواعد بيانات من داخل ملفات موقع ثابت. لا تدّعِ تشغيل هذه الميزات قبل وجود VPS وتطبيقها واختبارها.

Cloudflare Pages يتولى التوزيع الطرفي ويقدم Gzip/Brotli متى أمكن، ويعرض `404.html` تلقائيًا للمسارات غير الموجودة. صفحة `500.html` المرفقة قالب يدوي وليست تهيئة تلقائية لحالة HTTP 500.

## النشر على Cloudflare Pages

### Git integration (موصى به للتحديث التلقائي)

1. من Cloudflare Dashboard افتح **Workers & Pages → Create application → Pages → Connect to Git**.
2. اختر مستودع GitHub هذا: `4amd913-create/abubaraax1`.
3. اجعل فرع الإنتاج `main`.
4. اترك **Build command** فارغًا.
5. اجعل **Build output directory** هو `.` (جذر المستودع).
6. أكمل **Save and Deploy**.

بعد ربط Git integration، كل تحديث يُدمَج في `main` سيؤدي إلى بناء ونشر تلقائي. الفروع الأخرى يمكن استخدامها لمعاينات Preview Deployments.

**تنبيه:** لا يمكن تحويل مشروع Cloudflare Pages الذي أُنشئ أصلًا بطريقة Direct Upload إلى Git integration. أنشئ مشروع Pages جديدًا متصلًا بـ GitHub، ثم انقل الدومين إليه بعد نجاح النشر.

### الدومين وHTTPS

أضف دومينًا تملكه من Pages → Custom domains واتبع إعداد DNS الذي تعرضه لوحة Cloudflare. انتظر حتى تصبح شهادة HTTPS نشطة، ثم فعّل Always Use HTTPS واختبر HTTP وHTTPS. فعّل HSTS بعد التحقق من أن الدومين وكل النطاقات الفرعية المطلوبة تعمل عبر HTTPS.

لا يوجد دومين محدد في الملفات، لذلك لم نضف سجل DNS تخمينيًا أو قيمة canonical غير حقيقية.

## المراقبة والنسخ الاحتياطي

- راقب الصفحة الرئيسية و`/request.html` عبر خدمة uptime مستقلة.
- احتفظ بمصدر الموقع في Git.
- لا توجد قاعدة بيانات أو ملفات عملاء على النسخة الحالية، لذلك لا توجد مهمة نسخ DB يومية أو اختبار استعادتها الآن.
- عند إضافة VPS/قاعدة بيانات، اتبع `docs/PRODUCTION-READINESS.md` لتأمين SSH والجدار الناري وFail2ban والتحديثات وNginx/TLS والخدمة والنسخ خارج الخادم واختبار الاستعادة والمراقبة وتدوير السجلات.

## قبل الإطلاق التجاري

راجع `privacy.html` و`terms.html` واستبدل صياغة المسودة ببيانات النشاط الحقيقية وسياسة الاحتفاظ والدعم والاسترجاع وSLA والاستخدام المقبول. أجرِ مراجعة قانونية محلية. لا تبدأ تحصيل الأموال أو الإعلان عن توفر VPS اعتمادًا على هذه الواجهة وحدها.
